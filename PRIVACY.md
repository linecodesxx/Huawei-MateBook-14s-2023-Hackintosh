# Публикация без уникальных идентификаторов

**Русский** | [English](PRIVACY.en.md)

## Что разрешено

Модель ноутбука/платы, модель CPU, стандартные PCI/USB IDs, обезличенные ACPI-пути, проверенные выводы, ссылки на публичные проекты и собственные минимальные патчи после проверки.

В репозитории остаются [выжимка результатов](devlog/2026-11-05-recovery-and-input.md), [основные настройки](docs/recovery-settings.json) и собственные ACPI-патчи DSL после проверки. Полный архив экспериментов и исторические конфигурации хранятся локально. Проверка публикации не подтверждает загрузку или пригодность настроек для другого устройства.

## Что остаётся локально

- Реальные SystemSerialNumber, MLB, ROM, SystemUUID и другие PlatformInfo-идентификаторы.
- Серийные номера ноутбука, платы, накопителей и USB-устройств.
- MAC-адреса, Bluetooth-адреса, SSID, IP-адреса.
- Имя пользователя, домашние пути и личная почта.
- Windows OEM-ключи и MSDM-таблица.
- Токены, пароли, приватные ключи и конфигурации VPN.
- Полные EFI и их архивы, исходные NVRAM/IORegistry/SysReport и дампы памяти/прошивки.
- Необработанные аппаратные отчёты, полные родные DSDT/ACPI-таблицы, бинарные файлы, фотографии и скриншоты.

## Перед коммитом

1. Добавить только конкретные проверенные файлы; не переносить целиком каталог с диагностикой.
2. Просмотреть staged diff и список файлов.
3. Запустить python3 scripts/check_publication.py.
4. Убедиться, что сообщения коммитов и автор используют публичные данные; для email автора подходит GitHub noreply.
5. Проверить предыдущую историю перед первым push.

Проверка читает staged/index-содержимое, а не только текущую версию файла на диске. Иначе секрет, оставшийся в staging, можно пропустить после редактирования рабочей копии.

.gitignore не удаляет уже отслеживаемые файлы и не очищает историю. Проверка — защитная мера, а не гарантия отсутствия любых персональных данных. Она блокирует исходные приватные форматы и бинарные файлы, но не проверяет EXIF, вложения Issues и файлы по внешним ссылкам. Публикуемые материалы поэтому остаются текстовыми и требуют ручной проверки.

## Обезличенные конфигурации JSON

Публикуется только проверенная краткая выжимка настроек JSON с пустыми уникальными идентификаторами. В JSON проверка допускает только пустую строку, null, пустой массив или пустой объект для полей идентификации; непустой заполнитель также отклоняется. Идентификаторы нужно удалить и из вложенных структур, текстовых комментариев и кодировок. Исходный config.plist и полные исторические копии остаются локально; переименование файла не заменяет очистку. Исходные plist, AML, логи, EFI-каталоги, архивы и изображения по-прежнему запрещены проверкой.

## Общие GUID протоколов и типов

Исключения ограничены следующими общими константами; UUID устройства, тома и вложения не входят в этот список:

- 7C436110-AB2A-4BBB-A880-FE41995C9F82 — пространство Apple boot NVRAM.
- 4D1EDE05-38C7-4A6A-9CC6-4BCCA8B38C14 — пространство Apple vendor NVRAM.
- 4D1FDA02-38C7-4A6A-9CC6-4BCCA8B30102 — пространство OpenCore vendor NVRAM.
- 8BE4DF61-93CA-11D2-AA0D-00E098032B8C — пространство глобальных переменных UEFI.
- 3CDFF6F7-4267-4555-AD05-B30A3D8938DE — интерфейс ACPI _DSM HID-over-I2C.
- 4C616265-6C00-11AA-AA11-00306543ECAC — тип раздела Apple Label.
- 0516B563-B15B-11DA-96EB-0014519758EF — интерфейс IOCFPlugInTypes AppleMultitouch.
- 00000000-0000-0000-0000-000000000000 — пустой Nil UUID; это не разрешение непустого поля идентификации в JSON.

Назначения подтверждаются [OpenCore Reference Manual, §9.1](https://raw.githubusercontent.com/acidanthera/OpenCorePkg/master/Docs/Configuration.pdf), [описанием HID-over-I2C от Microsoft](https://learn.microsoft.com/en-us/windows-hardware/drivers/bringup/hidi2c-device-specific-method---dsm-), [IOStorageFamily Apple](https://github.com/apple-oss-distributions/IOStorageFamily/blob/main/Info.plist), [метаданными VoodooI2C](https://github.com/VoodooI2C/VoodooI2C/blob/6be653a2d2234ac1f7464ebf12716314975c3920/VoodooI2C/VoodooI2C/Info.plist) и [RFC 9562, §5.9](https://www.rfc-editor.org/rfc/rfc9562.html#name-nil-uuid). Новое исключение требует проверки первоисточника и теста; совпадение формата UUID само по себе ничего не разрешает.

Если утечка произошла, удаление строки следующим коммитом недостаточно: нужно учитывать историю, доступные копии и ротацию раскрытых секретов.
