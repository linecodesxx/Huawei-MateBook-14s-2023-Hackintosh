# 01.11.2026 — Проверка Recovery и сбор диагностических данных

**Русский** | [English](2026-11-01-recovery-investigation.en.md)

## Наблюдения

- macOS Tahoe Recovery запускал ядро, но графический интерфейс Recovery не появился. Последние видимые строки менялись между `CoreAnalyticsHub start completed` и `pci (build ...)`.
- Для сравнения был подготовлен оригинальный Recovery macOS Sequoia **15.4.1, build 24E263**. Образ проверен по chunklist. Sequoia тоже дошла до раннего вывода ядра и ACPI, но экран Recovery не появился.
- Вывод об успешной загрузке ACPI-таблиц сопровождался предупреждениями `Unsupported module-level executable opcode 0x70`. Часть указанных смещений совпадает с байтами в OEM SSDT13, но по этому совпадению нельзя установить источник всех предупреждений или причину остановки.
- В Linux обнаружены ACPI `AE_ALREADY_EXISTS` для методов `TPL1` и отдельная ошибка `AE_NOT_FOUND` в методе Wi-Fi; Linux работает. Причинная связь с macOS не установлена.

## Проверки

| Изменение / проверка | Результат и ограничение |
|---|---|
| Подмена CPUID в новой EFI | В последующей попытке вывод прошёл `EXITBS` и дошёл до ядра. Связь с конкретной частью подмены не доказана: попытки не были строго идентичны. |
| Виртуальный EC, не отключая HWEC | Видимого продвижения не отмечено. |
| `cpus=1`, `npci=0x2000`, `CpuTscSync` | По отдельности не дали наблюдаемого запуска Recovery в проверенных конфигурациях; это не исключает влияние сочетаний настроек. |
| Отключение USBToolBox и UTBDefault, смена `ReleaseUsbOwnership` | Не дали наблюдаемого запуска Recovery. Доступ к загрузочному носителю на этапе ядра остаётся непроверенным. |
| Диагностический форк WhateverXe | Видимого продвижения не отмечено; Metal и ускорение им не проверялись. |
| `io=0x16`, разрешение panic при тайм-ауте питания | Дополнительной причины на экране не получено. |
| Исключение runtime MMIO `0xF9D00000` | DEBUG-журнал подтвердил `skip 1`; видимого продвижения не было. Это не доказывает, нужен ли диапазон для конкретной функции прошивки. |
| Временное исключение OEM SSDT13 по сигнатуре, OEM Table ID и длине | Видимого продвижения не отмечено. Журнала применения нет, поэтому нельзя подтвердить, что исключение сработало. После теста оно отключено. |

Доступный журнал DEBUG OpenCore показывает три runtime-MMIO-дескриптора. Предыдущая запись `0xF9000000` не попадала внутрь наблюдавшегося дескриптора `0xF9D00000–0xF9EFFFFF`. Наличие дескриптора не доказывает, что его нужно включать в whitelist. Позднее был подготовлен отдельный тест `0xFF000000`, но подтверждённого результата запуска для него нет.

## Текущее состояние и следующий шаг

Рабочая EFI, Recovery GUI и графическое ускорение **не подтверждены**. На последнем проверенном конфиге исключение SSDT13 выключено; на тестовой флешке используется Tahoe Recovery 26.6.2, а ранее использованная Sequoia 15.4.1 сохранена отдельно. При загрузке через OpenCore ACPI-изменения могут затрагивать и другие ОС: Для запуска Windows и Linux рекомендовано использовать меню прошивки, пока эксперимент включён.

Следующая задача — получить данные о выполнении **после последней видимой строки ядра** или выбрать тест с заранее определённым ожидаемым результатом. Последняя строка экрана не определяет виновника. `ocvalidate` проверяет структуру конфигурации, а не аппаратную совместимость. Публичный EFI-релиз пока не готов.

## Дополнение: графика и USB

- Точную версию Tahoe Recovery определили по `SystemVersion.plist`: **26.6.2, 25G83**.
- Проверили экспериментальный WhateverXe 0.6.1 для GPU `8086:a7a0`: после замены WhateverGreen и удаления `-igfxvesa` Recovery снова завис. Лог подтвердил передачу параметров загрузки, но не показал, загрузился ли кекст. Тест не доказывает причину зависания: Tahoe 26.6.2 не входит в заявленные версии WhateverXe, а отдельный графический пакет не был установлен.
- `UTBDefault.kext` — универсальная заготовка, а не карта портов данного ноутбука. В Linux флешка подключена к `00:14.0` через SuperSpeed; работа этого порта в macOS на этапе ядра не подтверждена.
- Решили попробовать **Sequoia 15.8**: она перечислена среди совместимых версий WhateverXe. Запуск Recovery и графическое ускорение пока не подтверждены.
- Raptor Lake-H/P/U включён в [список WhateverXe](https://github.com/b00t0x/WhateverXe/blob/main/docs/device-selection.md), однако поддержка не проверена для этого ноутбука, а встроенный экран указан как экспериментальный.
